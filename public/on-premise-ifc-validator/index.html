On-premise IFC validator for networks that stay closed

The public app already reads IFC files inside the browser, but the page itself loads from the internet. Where that is not allowed, the same viewer, validator and IDS checks are served from a container on your own server.

Who it is for

When "nothing is uploaded" is not enough

It fits when

  • Workstations have no internet access, or may not load software from it.
  • You need one audited version that does not change until you decide.
  • Contractor models must be checked against your IDS or EIR without passing through a third party.
  • You want someone to call when it does not work.

You do not need it when

  • Your policy only forbids uploading models. The public validator does not upload them.
  • You have the staff to host it yourselves. The code is MIT-licensed and includes a Dockerfile: build the image and serve it. The pilot adds configuration, training and support, not a different product.

FAQ

Questions

Does anything leave our network?

No. The container serves the application to your browsers and makes no outbound connection; this build carries no usage statistics. Models are read in each user's browser and are not stored on the server.

What is different from the public app?

The program is the same. What changes is where it is served from, that it is a fixed version, and that the features needing the internet (the map context and the online sample models) are not available.

Can we host it ourselves without you?

Yes. The source is public under the MIT licence and includes a Dockerfile and an nginx configuration. The pilot is for teams that want it configured, explained and supported.

How large can the models be?

The same as in the public app: under 2 GB per file, limited in practice by the memory of each workstation, because the checking runs in the browser.

What does it cost?

A pilot is quoted after the scoping call, because it depends on the number of sites and the support you need. There is no public price list for it yet.
