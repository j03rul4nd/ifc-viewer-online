IFC Viewer SDK · v1.12.0

IFC ビューアを自社プロダクトに組み込む

同じブラウザビューアを CDE、デジタルツイン、社内のプロジェクトツールに組み込みます。各モデルはクライアント側で解析され、IFC データを自社アプリから直接読み込みます。

セットアップ

#クイックスタート

使っているスタックを選んでください。コピーして貼り付ければ描画されます — ビルド手順も API キーも不要です。

JavaScript は不要 — タグを任意のページやダッシュボードに置き、属性を設定するだけです。

effect でマウントし、アンマウント時に破棄します。React 18 StrictMode の二重実行にも安全です。

onMounted でマウントし、onUnmounted で破棄します。

ホスティング版とセルフホスト

各スニペットは当方の CDN から読み込みます。どのオリジンからでも動作します。セルフホストする場合は ifc-viewer.es.js を自社ドメインから配信してください — SDK はスクリプトからの相対位置でアプリの URL を自動的に解決します。アプリを別の場所に置いている場合は baseUrl オプションを指定してください。

npm パッケージはまだありません。URL でモジュールを読み込む（上記）か、ifc-viewer.es.js を自分のアプリに同梱してください。

アーキテクチャ

#仕組み

ページ側にはごく小さなラッパー、サンドボックス化された iframe には完全なビューア、その間をあなたのバイト列が渡り — データはもともとある場所で解析されます。

あなたのアプリ

iframe と型付き JS API を生成する約 6 KB の ES モジュール。3D や解析の重量はいっさいあなたのバンドルに入りません。

postMessage ブリッジ

IFC のバイト列は ArrayBuffer として iframe へ転送されます（ゼロコピー）。コマンドとクエリは対応付けられたリクエスト／レスポンスのメッセージです。

ビューア

three.js と WebAssembly にコンパイルされた web-ifc が、iframe の中でモデルを解析・描画します — 閲覧者のマシン上で。

なぜプライベートなのか

モデルがサーバーに届くことはありません。守るべきアップロード経路も、データ所在地の論点も、ファイルサイズ待ちの列もありません。

なぜスケールするのか

計算は閲覧者それぞれの端末で走ります。200 MB のモデルを配信するコストは 2 MB のものと同じ — ただの静的ファイルだからです。

コンセプト

#基本コンセプト

作り始める前に押さえておきたい 4 点。

マウントと準備完了

new IfcViewer(target) は即座にマウントし、ビューアの準備ができるまでコマンドをキューに入れます。await IfcViewer.create(target)（または whenReady()）ならすぐに使えるインスタンスが得られます。

バイト列か URL か

add(name, bytes) は手元にあるバイト列を渡します — CORS は不要で、何もアップロードされません。バッファは転送される（detached になる）ため、後でも必要ならコピーを渡してください。addFromUrl(url) は CORS 対応の公開 URL を取得します。

イベント

on(event, cb) で購読すると、購読解除用の関数が返ります。ready、model-progress、model-loaded、validation-completed、model-error、element-selected が利用できます。

クエリ

必要なときにデータを取得します：getModels、getElement、getValidation、getStats、getIssues、checkIds、checkEir、screenshot。いずれもリクエスト／レスポンス方式で、タイムアウト後に reject します（30 秒。IDS / EIR は最大 120 秒）。

リファレンス

#API リファレンス

すべてのメソッドをグループ別に — シグネチャと戻り値の型つきで。続いてコンストラクタのオプション、イベント、<ifc-viewer> Web component を掲載します。

コンストラクタ

new IfcViewer(target, options?)IfcViewer

CSS セレクタまたは要素にマウント。下のオプションを参照。

IfcViewer.create(target, options?)Promise<IfcViewer>

ビューアを生成し、コマンドを受け付けられる状態になったら解決します。

モデルの読み込み

add(name, bytes)Promise<ModelLoadedEvent>

自社アプリから IFC バイト（ArrayBuffer/Uint8Array）を読み込みます。バッファはゼロコピーで転送されます。

addFromUrl(url, name?)Promise<ModelLoadedEvent>

CORS 対応の公開 IFC URL を読み込みます。

removeModel(modelId)void

id でモデルをアンロードします。

clear()void

読み込み済みのモデルをすべて削除します。

カメラと選択

select(expressId, modelId?)void

IFC expressID で要素を選択してフレーミングします。

setView(view)void

カメラビューへ移動: iso, top, front, right, left, back, bottom。

fit() · reset()void

アクティブなモデルにフィット / カメラをリセット。

setCamera(position, direction)void

カメラを指定位置に置き、指定方向を向かせます。

getCamera()Promise<CameraState | null>

カメラの位置と注視点——保存して lookAt で復元できます。

lookAt(position, target, animate?)Promise<void>

カメラを指定位置へ移動し、ターゲットを注視（シーン単位メートル、Y が上）。

setWalkMode(enabled, { speed? })Promise<WalkState>

一人称のウォークモード（WASD で移動、ドラッグで見回し、Esc で終了）。walk-changed を発行。

getWalkState()Promise<WalkState>

ウォークモードが有効か、その速度。

表示・非表示

isolate(ifcType?)void

カテゴリを分離（例: "IfcWall"）。省略でクリア。

showAll()void

表示を全復元（非表示・分離を解除）。

hideElements(ids, modelId?) · showElements(ids, modelId?)void

expressID で要素の集合を非表示 / 表示します。

setModelVisible(modelId, visible)Promise<void>

統合シーン内のモデルをアンロードせずに表示／非表示。

setModelOpacity(opacity, modelId?)Promise<void>

モデルを半透明に（0.05–1）——例：設備の周りの意匠。

isolateModel(modelId | null)Promise<void>

このモデルのみ表示。null ですべて再表示。

外観と表示

setBackground(background)Promise<BackgroundState>

シーン背景を変更：プリセット（'white'、'paper'、'blueprint'、'sky'、'studio'）、'#rrggbb'、'#上,#下'、または { top, bottom }。訪問者自身の設定としては保存されません。

getBackground()Promise<BackgroundState>

現在のシーン背景。

setAccent(color)Promise<void>

実行時に UI のアクセントカラーを変更（#rrggbb）。

setClientMode(enabled)Promise<void>

クライアント表示のオン／オフ——関係者向けの表示で、ui: 'client' と同じです。

setRenderQuality(quality)Promise<void>

'quality' はメインビジュアル用の重いレンダリングを有効化。普段は 'standard'。

日照スタディ

setSolar(opts?)Promise<SolarState>

敷地の現地日時でのリアルな影：{ date: '06-21', time: '18:00' }。敷地は IFC のジオリファレンスから取得。ない場合は location を渡してください——既定の都市を黙って使うことはありません。

getSolar()Promise<SolarState>

スタディの日付・時刻・タイムゾーンと敷地の位置。

マップモード

setSiteContext(opts?)Promise<SiteContextState>

モデルを地形と OpenStreetMap の周辺環境とともに地図上に配置。呼び出しは、あなたのページが訪問者に代わってタイル利用に同意することを意味します。帰属表示を表示してください。

getSiteContext()Promise<SiteContextState>

マップモードの状態、配置、表示が必要な帰属表示。

断面

addSection({ axis?, offset?, level?, flip? })Promise<SectionsState & { id }>

断面を追加。{ level: '1階' } はその階の平面図、{ axis: 'x', offset: 4.5 } は 4.5 m の断面。

updateSection(id, { offset?, enabled?, flipped? })Promise<SectionsState>

断面の移動、有効／無効、反転。

removeSection(id?)Promise<SectionsState>

断面を 1 つ削除。id を省略するとすべての切断を削除。

setSectionBox('model' | 'selection' | false)Promise<SectionsState>

モデルまたは選択範囲を囲むセクションボックス。false で削除。

getSections()Promise<SectionsState>

すべての断面、ボックス、階ごとの切断に使える階の一覧。

ツアー

startTour(template?, { autoplay?, title? })Promise<TourState>

組み込みツアーを開始：'social'、'client-walkthrough'、'technical-review'（検証の指摘を順に確認）。ビューア自身のツアーバーで再生されます。

playTour({ title?, steps }, { startAt?, autoplay? })Promise<TourState>

自作のツアーを再生：キャプション、ハイライト、分離するクラス付きのカメラ停留点。autoplay は true または停留点ごとの ms。

nextTourStep() · prevTourStep() · goToTourStep(i)Promise<TourState>

停留点を移動。

setTourAutoplay(autoplay)Promise<TourState>

再生中のツアーの自動送りをオン／オフ。

stopTour()Promise<TourState>

ツアーを停止してカメラを戻します。

getTour()Promise<TourState>

ツアーとその停留点（playTour() と同じ形式）——保存して後で再生できます。

プレゼンテーション・ディレクター

getPresentationRecipes()Promise<PresentationRecipe[]>

組み込みのディレクターレシピ（会議デモ、リール、LinkedIn ティーザー、ローンチ、エディトリアルなど）。

createPresentation(recipe?, options?)Promise<PresentationState>

レシピからモデルを編集済み動画に：IFC から計画したショット、キャプション、音楽。結果を Clip Studio で開きます。進捗は presentation-progress で。

exportPresentation({ resolution?, music? })Promise<PresentationVideo>

訪問者のブラウザでプレゼンテーションをエンコードし、MP4 のバイトを返します——アップロード、添付、<video> での再生に。

closePresentation()Promise<void>

Clip Studio を閉じます。

計測

setMeasureTool(tool)Promise<void>

訪問者向けに計測ツールを有効化（計測パネルを開きます）、または 'none'。結果は measurements-changed で届きます。

getMeasurements()Promise<MeasurementsState>

画面上のすべての計測。値は常に SI 単位——m、m²、度——表示とは無関係です。

clearMeasurements(id?)Promise<MeasurementsState>

計測を 1 つ、またはすべて削除。

クエリ

getModels()Promise<ModelSummary[]>

読み込み済みモデルを列挙。Promise を返します。

getElement(id, modelId?)Promise<IfcElementData | null>

要素の IFC データ（属性＋プロパティ/数量セット）を取得。Promise を返します。

getValidation()Promise<ValidationSummary | null>

現在の検証サマリ（ヘルススコア＋件数）を取得。Promise を返します。

getStats()Promise<StatsResult>

モデルごとのカテゴリ別要素数 — ダッシュボードのグラフ用。Promise を返します。

getIssues(opts?)Promise<IssuesResult>

テーブル用の検証問題（重大度 / 件数でフィルタ）。Promise を返します。

screenshot()Promise<string>

現在の 3D ビューを PNG data URL として取得。Promise を返します。

パネル

openPanel(panel | null) · closePanel()void

ツールパネルを開きます。null を渡すと開いているパネルを閉じます。利用できないパネル（クロームが隠している、または対象となる読み込み済みデータがない）は何も起こらず、エラーにもなりません。

getPanels()Promise<PanelsResult>

現在開いているパネルと、この時点で提供されているパネル。`available` にないツールは開けません。単に無効化されているのではありません。

setPanels(panels)void

実行時にレールをこれらのパネルに限定します。URL パラメータ `panels=` と同じ語彙で、そちらより優先されます。ビューアが提供するものを絞るだけで追加はしません。空配列はレールなしを意味します。

点群

addPointCloud(fileName, bytes)Promise<string>

バイト列からスキャンを読み込みます——LAS、LAZ、COPC、PLY、PCD、テキスト。バッファーはコピーではなく転送され、点群 id を返します。

addPointCloudFromUrl(url, fileName?)Promise<string>

ビューアー自身が取得するスキャンを読み込みます。URL は CORS を許可している必要があります。

listPointClouds()Promise<PointCloudInfo[]>

読み込み済みのすべてのスキャン。`pointCount` は常駐している数、`declaredCount` はファイルが持つ数で、予算が解析を打ち切ったときに食い違います。

removePointCloud(cloudId) · clearPointClouds()Promise<void>

スキャンを 1 つ解放して GPU バッファーを返すか、すべて解放します。

setPointCloudVisible(cloudId, visible)Promise<void>

スキャンを解放せずに表示・非表示を切り替えます。

fitPointCloud(cloudId?)Promise<void>

カメラをスキャンに、または最初に読み込んだものに合わせます。

setPointCloudDisplay(display, renderBudget?)Promise<void>

点サイズ、不透明度、配色、密度、信頼度しきい値——すべてのスキャンで共通です。いずれもシェーダーの uniform なので、2000 万点でも即座に反映されます。

inspectPointCloud(enabled?)Promise<void>

クリックで読み取るモードを有効にします。有効な間、点をクリックすると `pointcloud-picked` がシーン座標とファイル内の座標の両方を伴って発火します。

setPointCloudPlacement(placement, cloudId?)Promise<void>

スキャンを手で微調整します——位置、ヨー、水平出し、スケール。部分指定でき、値はクランプされます。導出された位置合わせを置き換えず、その上に乗ります。

setPointCloudUpAxis(axis, cloudId?)Promise<void>

スキャンがどの軸を上とみなすかを修正します。PLY、PCD、テキストは方向を宣言しないためビューアーが推定します——`upAxisSource` を確認してください。

Imported 3D models

addMesh(files)Promise<string>

バイト列からモデルを取り込みます。リストを受け取ります：.gltf には .bin とテクスチャー、.obj には .mtl が必要で、入口ファイルだけではグレーのジオメトリーになります。

addMeshFromUrl(urls)Promise<string>

ビューアーが取得するモデルを取り込みます。必要な URL をすべて渡してください。並列に取得され、すべて CORS を許可している必要があります。

listMeshes()Promise<MeshInfo[]>

取り込み済みのすべてのモデルと、その三角形数・テクスチャー数。隣の値を信頼する前に `unitSource` と `upAxisSource` を読んでください。

removeMesh(meshId?) · clearMeshes()Promise<void>

取り込みを 1 つ削除してジオメトリー・マテリアル・テクスチャーを解放するか、すべて削除します。

setMeshVisible(visible, meshId?)Promise<void>

取り込みを解放せずに表示・非表示を切り替えます。

fitMesh(meshId?)Promise<void>

カメラを 1 つの取り込みに、またはすべてに合わせます。

setMeshPlacement(placement, meshId?)Promise<void>

取り込みを手で配置します——位置、ヨー、水平出し、スケール。部分指定でき、クランプされます。取り込みは IFC の中央、その床の上から始まります。

setMeshUpAxis(axis, meshId?)Promise<void>

ソースの上方向の軸を修正します。意味があるのは OBJ だけです——glTF は仕様で Y を上と定めているため `upAxisSource: 'declared'` を返します。

setMeshUnit(unitScale, meshId?)Promise<void>

ソースの単位を修正します：1 メートル、0.01 センチメートル、0.001 ミリメートル、0.3048 フィート。どの形式も単位を記録しないため、ビューアーがモデルの大きさから推定します。

IDS / EIR 適合性

checkIds(idsXml)Promise<IdsResult>

モデルを buildingSMART の IDS（.ids XML）と照合します。ワーカー内で実行され、仕様ごとの合否を返します。

checkEir(profile)Promise<IdsResult>

モデルを EIR / BIM 検証プロファイル（オブジェクトまたは JSON、簡易記法も可）と照合します。IDS にコンパイルされ同じエンジンで実行されます — checkIds と同じ IdsResult 構造です。

言語

setLanguage(lang)void

実行時に UI 言語を変更します。

getLanguages()string[]

対応言語コードを列挙（ラベルは IfcViewer.LANGUAGES）。

ライフサイクルとイベント

whenReady()Promise<void>

ビューアがコマンドを受け付けられる状態になったら解決します。

isReadyboolean

ゲッター — ビューアが準備完了を通知した時点で true になります。

on(event, cb)() => void

イベントを購読。解除用の関数を返します。

off(event, cb)void

以前に追加したイベントリスナーを削除します。

dispose()void

ビューアを破棄して iframe を削除します。

同時に呼ばれた add() / addFromUrl() は内部で直列化され、各 Promise はそれぞれの読み込みに対応づけられます — アプリ側で始まった読み込み（URL パラメータ、iframe 内でのアップロード）があなたの add() の Promise を解決することはありません。

#トラブルシューティング

つまずきやすいのは、ほんの数点です。

何も描画されません

順に確認してください：ビューアが ready に到達したか、モデルが読み込まれたか（model-error ではなく model-loaded か）、コンテナの高さがゼロでないか、バイト列が正しい IFC か。原因は model-error のメッセージに示されます。

モデルの読み込みで CORS エラーになります

CORS が関係するのは addFromUrl(url) だけです。バイト列を自分で扱えるなら、自分で取得して add(name, bytes) を呼んでください — データを直接渡すので CORS は関係しません。

iframe が真っ白、または読み込まれません

アプリが埋め込み可能である必要があります — ホスト側に X-Frame-Options: DENY や厳しい frame-ancestors の CSP があってはいけません。当方のホスティング版は埋め込みを許可しています。

add() のあと ArrayBuffer が空になります

add() はゼロコピーで受け渡すためにバッファを転送し、その結果あなたのコード側では detached になります。あとでもバイト列が必要ならコピー（bytes.slice(0)）を渡してください。

読み込みやクエリがタイムアウトします

add()/addFromUrl() は loadTimeout 後に reject します（既定 120 秒。0 で無効）。クエリは 30 秒、checkIds は 120 秒です。低速な端末で大きなモデルを扱う場合は loadTimeout を大きくしてください。

対応ブラウザは？

WebAssembly と ES モジュールに対応した最新のブラウザであれば動作します — Chrome、Edge、Firefox、Safari。Internet Explorer は対象外です。

ローカルの開発サーバーで 404 になります

SPA の開発サーバーが HTML フォールバックで /sdk/ を横取りすることがあります。実際のビルドや静的ホスティングで試すか、/sdk/ifc-viewer.es.js モジュールを直接 import してください。

IFC ビューアをどこにでも埋め込めます。ブラウザで解析し、アップロードはしません。

モデルは訪問者のブラウザで取得され、WebAssembly によりクライアント側で解析されます — 当社サーバーには何もアップロードされません。
