Mise en place

#Démarrage rapide

Choisissez votre stack. Copiez, collez, affichez — sans étape de build, sans clé d’API.

Zéro JavaScript — placez la balise dans n’importe quelle page ou tableau de bord et définissez les attributs.

Montez dans un effect, démontez au unmount. Sûr avec la double invocation du StrictMode de React 18.

Montez dans onMounted, libérez dans onUnmounted.

Hébergé par nous ou par vous

Les extraits importent depuis notre CDN, qui fonctionne sur n’importe quelle origine. Pour l’héberger vous-même, servez ifc-viewer.es.js depuis votre propre domaine — le SDK découvre l’URL de l’application relativement au script. L’application est ailleurs ? Utilisez l’option baseUrl.

Pas encore de paquet npm : importez le module par URL (ci-dessus) ou intégrez ifc-viewer.es.js à votre application.

Architecture

#Comment ça marche

Un wrapper minuscule dans votre page, le visualiseur complet dans un iframe isolé, vos octets transmis entre les deux — et analysés là où ils se trouvent déjà.

Votre application

Un module ES de ~6 Ko qui crée un iframe et une API JS typée. Rien du poids 3D ni de l’analyse ne touche votre bundle.

Pont postMessage

Les octets IFC sont transférés à l’iframe sous forme d’ArrayBuffer (sans copie). Les commandes et les requêtes sont des messages requête/réponse corrélés.

Le visualiseur

three.js + web-ifc compilé en WebAssembly analysent et affichent le modèle dans l’iframe — sur la machine du visiteur.

Pourquoi c’est privé

Les modèles n’atteignent jamais un serveur. Aucun pipeline de téléversement à sécuriser, aucune question de résidence des données, aucune file d’attente liée à la taille des fichiers.

Pourquoi ça passe à l’échelle

Le calcul s’exécute sur l’appareil de chaque visiteur. Servir un modèle de 200 Mo coûte autant qu’un de 2 Mo — c’est un fichier statique.

Concepts

#Concepts essentiels

Quatre choses à savoir avant de construire.

Montage et disponibilité

new IfcViewer(target) monte immédiatement et met les commandes en file d’attente jusqu’à ce que le visualiseur soit prêt. await IfcViewer.create(target) (ou whenReady()) vous donne une instance utilisable tout de suite.

Octets ou URL

add(name, bytes) transmet des octets que vous avez déjà — pas de CORS, rien de téléversé ; le buffer est transféré (détaché), passez donc une copie si vous en avez encore besoin. addFromUrl(url) récupère plutôt une URL publique avec CORS.

Événements

Abonnez-vous avec on(event, cb), qui renvoie une fonction de désabonnement. Vous disposez de ready, model-progress, model-loaded, validation-completed, model-error et element-selected.

Requêtes

Récupérez les données à la demande : getModels, getElement, getValidation, getStats, getIssues, checkIds, checkEir, screenshot. Chacune est en requête/réponse et échoue après un délai (30 s ; IDS / EIR jusqu’à 120 s).

getSolar()Promise<SolarState>

Date, heure et fuseau de l'étude, et où se trouve le site.

Mode carte

Place le modèle sur la carte avec le relief et les environs OpenStreetMap. L’appeler, c’est votre page qui déclare le consentement aux tuiles pour ses visiteurs ; affichez les attributions.

État du mode carte, le placement et les attributions à afficher.

Coupes

getSections()Promise<SectionsState>

Tous les plans, la boîte et les niveaux disponibles pour les coupes par étage.

Visites

Arrête la visite et rend la caméra.

La visite et ses arrêts, au format de playTour() — enregistrez-la, rejouez-la plus tard.

Les recettes intégrées du réalisateur (démo de réunion, reel, teaser LinkedIn, lancement, looks éditoriaux…).

Encode la présentation dans le navigateur du visiteur et renvoie les octets du MP4 — à téléverser, joindre ou lire dans une <video>.

Les recettes, modèles, formats et palettes du studio de couvertures.

Tous les groupes de la scène — déduits de l’IFC (projet, site, localisation) et créés par les utilisateurs.

Toutes les mesures à l'écran. Valeurs en SI — mètres, m², degrés — quel que soit l'affichage.

Retire une mesure, ou toutes.

getModels()Promise<ModelSummary[]>

Liste les modèles chargés. Renvoie une promesse.

Récupère les données IFC d'un élément (attributs + property/quantity sets). Renvoie une promesse.

Récupère le résumé de validation (Health Score + compteurs). Renvoie une promesse.

Panneaux

openPanel(panel | null) · closePanel()void

Ouvre un panneau d'outil, ou null pour fermer celui qui est ouvert. Un panneau indisponible — masqué par le chrome, ou sans contenu sur lequel agir — ne fait rien et n'est pas une erreur.

getPanels()Promise<PanelsResult>

Quel panneau est ouvert et lesquels sont proposés à cet instant. Un outil absent de `available` ne peut pas être ouvert ; il n'est pas simplement désactivé.

setPanels(panels)void

Limite la barre à ces panneaux, à l'exécution. Même vocabulaire que le paramètre d'URL `panels=`, et il prime sur lui. Restreint ce que le visualiseur propose et n'ajoute jamais ; un tableau vide signifie aucune barre.

Nuages de points

addPointCloud(fileName, bytes)Promise<string>

Charge un relevé depuis des octets — LAS, LAZ, COPC, PLY, PCD ou texte. Le tampon est transféré, pas copié. Résout avec l'identifiant du nuage.

addPointCloudFromUrl(url, fileName?)Promise<string>

Charge un relevé que le visualiseur récupère lui-même. L'URL doit autoriser CORS.

listPointClouds()Promise<PointCloudInfo[]>

Tous les relevés chargés. `pointCount` est ce qui réside en mémoire, `declaredCount` ce que contient le fichier — ils diffèrent quand le budget a tronqué l'analyse.

removePointCloud(cloudId) · clearPointClouds()Promise<void>

Décharge un relevé et libère ses tampons GPU, ou décharge-les tous.

setPointCloudVisible(cloudId, visible)Promise<void>

Affiche ou masque un relevé sans le décharger.

fitPointCloud(cloudId?)Promise<void>

Cadre la caméra sur un relevé, ou sur le premier chargé.

setPointCloudDisplay(display, renderBudget?)Promise<void>

Taille des points, opacité, mode de couleur, densité, seuil de confiance — partagés par tous les relevés. Chacun est un uniform de shader, donc instantané sur 20 millions de points.

inspectPointCloud(enabled?)Promise<void>

Arme le clic-pour-lire. Une fois armé, cliquer un point émet `pointcloud-picked` avec les coordonnées DU FICHIER à côté de celles de la scène.

setPointCloudPlacement(placement, cloudId?)Promise<void>

Ajuste un relevé à la main : position, lacet, mise à niveau, échelle. Partiel et borné ; s'applique par-dessus l'alignement déduit sans le remplacer.

setPointCloudUpAxis(axis, cloudId?)Promise<void>

Corrige l'axe que le relevé considère comme vertical. PLY, PCD et texte ne déclarent aucune orientation, le visualiseur la déduit — vérifiez `upAxisSource`.

Imported 3D models

addMesh(files)Promise<string>

Importe un modèle depuis des octets. Prend une LISTE : un .gltf a besoin de son .bin et de ses textures, un .obj de son .mtl — seul, le fichier d'entrée donne de la géométrie grise.

addMeshFromUrl(urls)Promise<string>

Importe un modèle que le visualiseur récupère. Passez toutes les URL nécessaires ; elles sont récupérées en parallèle et doivent toutes autoriser CORS.

listMeshes()Promise<MeshInfo[]>

Tous les modèles importés, avec leurs nombres de triangles et de textures. Lisez `unitSource` et `upAxisSource` avant de faire confiance aux valeurs voisines.

removeMesh(meshId?) · clearMeshes()Promise<void>

Retire un import et libère sa géométrie, ses matériaux et ses textures, ou retire-les tous.

setMeshVisible(visible, meshId?)Promise<void>

Affiche ou masque un import sans le décharger.

fitMesh(meshId?)Promise<void>

Cadre la caméra sur un import, ou sur tous.

setMeshPlacement(placement, meshId?)Promise<void>

Place un import à la main : position, lacet, mise à niveau, échelle. Partiel et borné. Un import démarre centré sur l'IFC, posé sur son sol.

setMeshUpAxis(axis, meshId?)Promise<void>

Corrige l'axe vertical de la source. Utile seulement pour OBJ — la spécification glTF impose Y vers le haut, elle rapporte donc `upAxisSource: 'declared'`.

setMeshUnit(unitScale, meshId?)Promise<void>

Corrige l'unité source : 1 mètres, 0,01 centimètres, 0,001 millimètres, 0,3048 pieds. Aucun de ces formats ne l'enregistre, le visualiseur la déduit de la taille du modèle.

Conformité IDS et EIR

checkIds(idsXml)Promise<IdsResult>

Vérifie le modèle par rapport à un IDS buildingSMART (XML .ids). S’exécute dans un worker. Renvoie réussite/échec par spécification.

checkEir(profile)Promise<IdsResult>

Vérifie le modèle par rapport à un profil EIR / de validation BIM (objet ou JSON, y compris la forme abrégée). Compilé en IDS et exécuté sur le même moteur — même structure IdsResult que checkIds.

Langues

setLanguage(lang)void

Changer la langue de l'interface à l'exécution.

getLanguages()string[]

Lister les codes de langue pris en charge (libellés via IfcViewer.LANGUAGES).

whenReady()Promise<void>

Se résout quand le visualiseur peut accepter des commandes.

isReadyboolean

Getter — true dès que le visualiseur a signalé qu’il est prêt.

on(event, cb)() => void

S’abonner à un événement ; renvoie une fonction de désabonnement.

Aide

#Dépannage

Les quelques points sur lesquels on trébuche.

Rien ne s’affiche

Vérifiez, dans cet ordre : que le visualiseur a atteint ready, que le modèle s’est chargé (model-loaded plutôt que model-error), que le conteneur a une hauteur non nulle et que la source d’octets est bien de l’IFC valide. Le message de model-error nomme la cause.

J’obtiens une erreur CORS au chargement d’un modèle

CORS ne concerne que addFromUrl(url). Si vous maîtrisez les octets, récupérez-les vous-même et appelez add(name, bytes) — CORS ne s’applique pas puisque vous transmettez les données directement.

L’iframe reste blanc ou refuse de se charger

L’application doit être intégrable — pas de X-Frame-Options: DENY ni de CSP frame-ancestors restrictive sur l’hôte. Notre application hébergée autorise l’intégration.

Mon ArrayBuffer est vide après add()

add() transfère le buffer pour une remise sans copie, ce qui le détache dans votre code. Passez une copie (bytes.slice(0)) si vous avez encore besoin des octets ensuite.

Les chargements ou les requêtes expirent

add()/addFromUrl() échouent après loadTimeout (120 s par défaut ; 0 désactive). Les requêtes échouent après 30 s, checkIds après 120 s. De gros modèles sur des appareils lents peuvent nécessiter un loadTimeout plus élevé.

Quels navigateurs sont pris en charge ?

Tout navigateur moderne à mises à jour continues avec WebAssembly et modules ES — Chrome, Edge, Firefox, Safari. Pas Internet Explorer.

J’obtiens un 404 sur mon serveur de développement local

Un serveur de développement SPA peut intercepter /sdk/ avec son fallback HTML. Testez contre un vrai build ou un hébergement statique, ou importez directement le module /sdk/ifc-viewer.es.js.
