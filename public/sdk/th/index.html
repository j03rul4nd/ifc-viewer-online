การติดตั้ง

#เริ่มต้นอย่างรวดเร็ว

เลือกสแตกของคุณ คัดลอก วาง แล้วเรนเดอร์ — ไม่ต้องมีขั้นตอน build ไม่ต้องใช้ API key

ไม่ต้องเขียน JavaScript — วางแท็กลงในหน้าเว็บหรือแดชบอร์ดใดก็ได้ แล้วกำหนดแอตทริบิวต์

mount ใน effect และคืนทรัพยากรตอน unmount ปลอดภัยกับการเรียกซ้ำสองครั้งของ StrictMode ใน React 18

mount ที่ onMounted และคืนทรัพยากรที่ onUnmounted

โฮสต์โดยเราหรือโฮสต์เอง

ตัวอย่างโค้ดนำเข้าจาก CDN ของเรา ซึ่งใช้ได้กับทุกออริจิน หากต้องการโฮสต์เอง ให้เสิร์ฟ ifc-viewer.es.js จากโดเมนของคุณ — SDK จะหา URL ของแอปโดยอ้างอิงตำแหน่งของสคริปต์เอง หากแอปอยู่ที่อื่น ให้กำหนดตัวเลือก baseUrl

ยังไม่มีแพ็กเกจ npm: นำเข้าโมดูลผ่าน URL (ด้านบน) หรือรวม ifc-viewer.es.js ไว้ในแอปของคุณ

#เดโมสด

หน้านี้กำลังรัน SDK คลิกปุ่มควบคุมเพื่อดึงไฟล์ IFC ตัวอย่างและสั่งงานตัวแสดงผล — แต่ละปุ่มจะแสดงเมธอดที่เรียกใช้

การเรียกล่าสุด —

⚠ โฮสต์ตัวอย่างอาจกำลังจำกัดอัตราการเรียก ลองใหม่อีกครั้งในอีกสักครู่

สถาปัตยกรรม

#ทำงานอย่างไร

ตัวห่อขนาดเล็กมากในหน้าเว็บของคุณ ตัวแสดงผลเต็มรูปแบบใน iframe ที่แยกออกมา ไบต์ของคุณส่งผ่านระหว่างกัน — และถูกประมวลผลในที่ที่มันอยู่แล้ว

แอปของคุณ

โมดูล ES ขนาด ~6 KB ที่สร้าง iframe และ JS API แบบมี type น้ำหนักของ 3D และการ parse ไม่แตะบันเดิลของคุณเลย

สะพาน postMessage

ไบต์ IFC ถูกโอนไปยัง iframe ในรูป ArrayBuffer (ไม่มีการคัดลอก) คำสั่งและคำค้นเป็นข้อความแบบ request/response ที่จับคู่กัน

ตัวแสดงผล

three.js และ web-ifc ที่คอมไพล์เป็น WebAssembly ทำการ parse และเรนเดอร์โมเดลภายใน iframe — บนเครื่องของผู้เข้าชม

ทำไมจึงเป็นส่วนตัว

โมเดลไม่เคยไปถึงเซิร์ฟเวอร์ ไม่มีสายการอัปโหลดให้ต้องดูแลความปลอดภัย ไม่มีคำถามเรื่องถิ่นที่อยู่ของข้อมูล ไม่มีคิวตามขนาดไฟล์

ทำไมจึงขยายตัวได้

การคำนวณเกิดขึ้นบนอุปกรณ์ของผู้เข้าชมแต่ละคน การเสิร์ฟโมเดล 200 MB มีต้นทุนเท่ากับ 2 MB — เพราะมันคือไฟล์สแตติก

แนวคิด

#แนวคิดหลัก

สี่เรื่องที่ควรรู้ก่อนลงมือสร้าง

การ mount และความพร้อม

new IfcViewer(target) จะ mount ทันทีและเก็บคำสั่งไว้ในคิวจนกว่าตัวแสดงผลจะพร้อม ส่วน await IfcViewer.create(target) (หรือ whenReady()) จะให้อินสแตนซ์ที่ใช้ได้ทันที

ไบต์หรือ URL

add(name, bytes) ส่งไบต์ที่คุณมีอยู่แล้ว — ไม่เกี่ยวกับ CORS และไม่มีการอัปโหลด บัฟเฟอร์จะถูกโอน (กลายเป็น detached) ดังนั้นให้ส่งสำเนาไปหากยังต้องใช้ ส่วน addFromUrl(url) จะดึงจาก URL สาธารณะที่เปิด CORS

อีเวนต์

สมัครรับด้วย on(event, cb) ซึ่งคืนฟังก์ชันสำหรับยกเลิกการสมัคร มีให้ใช้ทั้ง ready, model-progress, model-loaded, validation-completed, model-error และ element-selected

การสืบค้น

ดึงข้อมูลตามต้องการ: getModels, getElement, getValidation, getStats, getIssues, checkIds, checkEir, screenshot แต่ละตัวเป็นแบบ request/response และจะ reject เมื่อหมดเวลา (30 วินาที; IDS / EIR สูงสุด 120 วินาที)

คู่มือ

#สูตรสำเร็จ

รูปแบบที่คัดลอกไปวางได้ สำหรับสิ่งที่ทีมสร้างกันจริง ๆ

ตัวตรวจสอบอิลิเมนต์

คลิกในมุมมอง 3 มิติ แล้วอ่าน property set ของ IFC เข้าสู่แผงของคุณเอง

วิดเจ็ต Health Score

แสดงคะแนนคุณภาพของโมเดลและจำนวนปัญหาบนแดชบอร์ดของคุณ

ตรวจความสอดคล้องด้วย IDS

ตรวจกับ IDS ของ buildingSMART แล้วแสดงผลผ่าน / ไม่ผ่าน แยกตามข้อกำหนด

การตรวจสอบ EIR / BIM

รันโปรไฟล์ EIR ที่แก้ไขได้ (สไตล์ ISO 19650) — ไม่ต้องมีไฟล์ .ids ผลที่ไม่ผ่านจะมี GlobalId ของอิลิเมนต์ติดมาด้วย

ฉากสำหรับบทความบล็อก

พื้นหลังสีขาว โมเดลบนไซต์ของมัน และเงายามเย็นของวันครีษมายัน — กำหนดไว้ล่วงหน้า ไม่ต้องคลิก

ผังพื้นและการวัด

ตัดผังพื้นที่ชั้นตามชื่อ ให้ผู้อ่านวัด แล้วอ่านผลเป็นหน่วย SI

ทัวร์นำชมในบทความ

กำหนดจุดหยุดครั้งเดียวด้วย getCamera() แล้วปล่อยให้ทัวร์เล่นเองข้างเนื้อหา

วิดีโอของโมเดลจากหน้าของคุณ

สร้างงานนำเสนอด้วยสูตรแล้วรับไฟล์ MP4 กลับมา — ไม่ต้องอัดหน้าจอ ไม่ต้องอัปโหลด

หน้าปกสำหรับโพสต์ของคุณ

สร้างพินบน Pinterest หรือการ์ด LinkedIn ของโมเดลพร้อมชื่อเรื่องของคุณ แล้วรับไฟล์ PNG กลับมา

ปรับให้เข้ากับแบรนด์

จับคู่ตัวแสดงผลกับผลิตภัณฑ์ของคุณด้วยสีเน้นเพียงสีเดียว

ตัวเลือกภาษา

สร้างตัวเลือกจากภาษาที่มาพร้อมกับตัวแสดงผล

ความช่วยเหลือ

#การแก้ปัญหา

ไม่กี่เรื่องที่คนมักสะดุด

ไม่มีอะไรถูกเรนเดอร์

ตรวจตามลำดับนี้: ตัวแสดงผลถึงสถานะ ready แล้วหรือไม่, โมเดลโหลดสำเร็จหรือไม่ (model-loaded ไม่ใช่ model-error), คอนเทนเนอร์มีความสูงไม่เป็นศูนย์หรือไม่ และแหล่งไบต์เป็น IFC ที่ถูกต้องหรือไม่ ข้อความของ model-error จะบอกสาเหตุ

เจอข้อผิดพลาด CORS ตอนโหลดโมเดล

CORS มีผลเฉพาะกับ addFromUrl(url) หากคุณควบคุมไบต์ได้เอง ให้ดึงเองแล้วเรียก add(name, bytes) — ไม่มี CORS เข้ามาเกี่ยวข้อง เพราะคุณส่งข้อมูลให้โดยตรง

iframe ว่างเปล่าหรือไม่ยอมโหลด

แอปต้องฝังได้ — ต้องไม่มี X-Frame-Options: DENY และไม่มี CSP frame-ancestors ที่เข้มงวดบนโฮสต์ แอปที่เราโฮสต์อนุญาตให้ฝังได้

ArrayBuffer ของฉันว่างเปล่าหลังเรียก add()

add() จะโอนบัฟเฟอร์เพื่อส่งมอบแบบไม่คัดลอก ซึ่งทำให้มันกลายเป็น detached ในโค้ดของคุณ ให้ส่งสำเนา (bytes.slice(0)) หากยังต้องใช้ไบต์เหล่านั้นภายหลัง

การโหลดหรือการสืบค้นหมดเวลา

add()/addFromUrl() จะ reject หลังครบ loadTimeout (ค่าเริ่มต้น 120 วินาที; 0 คือปิดใช้งาน) การสืบค้นจะ reject ที่ 30 วินาที และ checkIds ที่ 120 วินาที โมเดลขนาดใหญ่บนอุปกรณ์ที่ช้าอาจต้องใช้ loadTimeout ที่สูงขึ้น

รองรับเบราว์เซอร์ใดบ้าง?

เบราว์เซอร์สมัยใหม่ที่อัปเดตต่อเนื่องและรองรับ WebAssembly กับ ES module — Chrome, Edge, Firefox, Safari ไม่รองรับ Internet Explorer

ได้ 404 บนเซิร์ฟเวอร์พัฒนาเครื่องผม

เซิร์ฟเวอร์พัฒนาแบบ SPA อาจดักเส้นทาง /sdk/ ด้วย HTML fallback ให้ทดสอบกับ build จริงหรือโฮสต์แบบสแตติก หรือนำเข้าโมดูล /sdk/ifc-viewer.es.js โดยตรง

ฝังตัวแสดงผล IFC ได้ทุกที่ ประมวลผลในเบราว์เซอร์ ไม่มีการอัปโหลด

โมเดลถูกดึงในเบราว์เซอร์ของผู้เข้าชมและแปลงที่ฝั่งไคลเอนต์ด้วย WebAssembly — ไม่มีการอัปโหลดไปยังเซิร์ฟเวอร์ของเรา
